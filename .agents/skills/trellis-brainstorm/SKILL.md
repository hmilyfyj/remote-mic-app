# Trellis Brainstorm

把用户需求收敛为有证据、可验收的规划。已授权的实现任务包含必要规划和实现，不要求用户在初始请求后再回复一次才可开工。用户明确要求先评估/先审方案时，交付该阶段后等待其决定。

## 澄清与取证

- 先查能回答问题的相关代码、配置、测试与文档；只读取当前任务所需内容。
- 缺少会影响产品行为、兼容、范围或验收的关键决定时，询问用户并说明选择影响；继续不依赖答案的调查。
- 普通实现细节按现有约定判断，不制造澄清问题，也不因为文档没有写死每个细节就停工。
- 用户意图以当前请求和已有授权为准；不要用仓库现状推翻用户明确的新需求。

## 任务与产物

仅对需要规划的任务创建或复用 task；纯问答不创建任务。

```bash
python3 ./.trellis/scripts/task.py create "<short task title>" --description "<one-line summary>" --slug <slug>
```

标题和描述非空；slug 不带日期前缀，脚本自动添加。更新创建的 prd.md，不保留空骨架。

- `prd.md`：目标、已验证事实与来源、需求、边界、可观察验收及未决问题。
- 复杂任务补 `design.md`：架构/数据流、接口约定、兼容迁移及取舍；补 `implement.md`：执行清单、验证与回滚点。
- 轻量任务可仅用 PRD。按项目 workflow 判定复杂度，不为短任务填长篇模板。
- 使用子代理调度时，implement.jsonl/check.jsonl 各需真实 spec/research 条目，不能仅有 `_example`；inline 模式通过 trellis-before-dev 读取相关规范。
- 收敛时合并重复事实，保留证据锚点、决定、约束与验收映射；已回答的问题不继续标为阻塞。

## 进入实现

确认规划覆盖用户目标、范围与验收，关键决定已解决，项目所需产物和上下文齐全。简述重要决定后，已获实现授权的任务直接 `task.py start` 并继续；无需新的确认轮次。

若用户只授权规划，或新发现确需扩大范围，则交付具体方案与待定问题。规划更新不自动撤销已有授权，只有实质超出授权的部分需要重新决定。
